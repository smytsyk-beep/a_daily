## 0) What is AstroDaily - TG Bot
AstroDaily — Telegram-бот с ежедневным астрологическим дайджестом и алертами, персональным календарём .ics и базовыми PDF-отчётами (Year Ahead, Compatibility и т.п.).

Что продаём:
Базовый продукт: ежедневные/еженедельные персональные прогнозы на основе натальной карты (дата/время/место), push-уведомления о транзитах, совместимость, «ритуалы/ффирмации дня».

Апсейлы: «Год вперёд», «Совместимость с партнёром», персональные PDF-отчёты, голосовые/чат-ридинги от человека, подарочные сертификаты.

Близкие тематики помимо гороскопа: нумерология, human design, таро (текст/картинка), лунный календарь, бiorhythm, «wellness-советы» (без медицинских обещаний).

Монетизация:
- Сначала Stripe (подписка), позже Telegram Stars
- Ориентиры цен:
    - Demo — onboarding + общий гороскоп + 1 персональный «тизер» + дразнящие алерты + обрезанный текст (cap).
    - Basic $0.99/мес — персональные daily/weekly, 2 отчёта/мес, 1 профиль.
    - Pro $4.99/мес — все отчёты, алерты по транзитам, до 5 профилей, PDF-экспорт, календарные события.

Yearly $39/год (-35–45% к месячному).

MVP-план
Онбординг: дата/время/место рождения → расчёт натала → 1 бесплатный персональный «снапшот».

Чем AstroDaily - TG Bot выигрывает:

- Персональные алерты по транзитам в реальном времени с тонкой настройкой (категории/типы событий).

- Календарная интеграция: экспорт событий в Google/Apple Calendar (+ тихие напоминания).

- PDF-отчёты в один тап: «Год вперёд», «Совместимость», «Неделя по домам/аспектам».

- Мультипрофильность (семья/партнёр/друзья) с быстрым свитчем прямо в чате.

- Нативные TG-механики: инлайн-кнопки, квизы/тесты, «ежедневная карта/ритуал» в карусели, реферальные deeplink-линки.

- Гибкая локальная цена + «легкий» триал (48–72 часа) под Stripe-чекаутом; Stars — вторым вариантом внутри TG.

- Авто-тональность: адаптация текстов под настроение/цель пользователя (wellness, отношения, работа).

- A/B-контент: 2–3 формулировки на один и тот же транзит → максимизация удержания.

- Анти-спам UX: «тихий режим», дайджест 1×/день, ручной snooze, «без ретроградного clickbait».

- Прозрачные дисклеймеры («for entertainment») и возрастные ограничения (18+) на онбординге — снижение рисков в США.

Источник данных (точная астрономия, офлайн):
- Эфемериды: (open-source стек): Skyfield + JPL DE440/DE430 бинарные файлы (*.bsp).
- Подтверждение стандарта/точности: DE440/DE441 — актуальные планетарно-лунные эфемериды JPL (peer-reviewed описание).

Геокодинг/таймзона:
- self-hosted Nominatim (OSM) либо платный API (чтобы не упереться в лимиты общего сервера OSM). nominatim.org+1
- Таймзона по координатам — офлайн-модуль timezonefinder (без внешних вызовов).

Что вычисляем:
- Натальная карта на онбординге: долготы планет, уголовые точки (ASC/MC), дома (Whole Sign/Placidus).
- Ежедневные транзиты к наталу: аспекты (☌, △, ✶, □, ☍), орбисы/скорость, апогеи «силы» события.
- Календарь событий: фазы Луны, ретроградности, ингрессии, — для общего слоя контента. (В Skyfield всё считается локально по JPL.

«Атомы смысла» (наша собственная база знаний):
- Создаём внутренний датасет коротких нейтральных трактовок, чтобы не зависеть от чужих текстов/лицензий:
Матрица: [Транзитная планета] × [Аспект] × [Натальная планета/точка] × [Дом/Сфера]
Для каждого сочетания: 2–3 микроабзаца (50–120 слов), теги (отношения/работа/деньги/самочувствие/креатив/коммз).

- Пишем оригинальные тексты (без копирования), чтобы избежать проблем с авторским правом и CC-SA «заражения» лицензией. (Открытые источники вроде Википедии можно использовать лишь как справку — у них CC BY-SA, что потребует атрибуции и share-alike; для таро-модулей это допустимо, но лучше создать свои формулировки.)

- Генерация текста (шаблоны + LLM)
RAG-пайплайн: по событиям дня подбираем релевантные «атомы» → подаём их как фактический контекст в LLM → на выходе получаем 1–2 абзаца + заголовок + CTA.

- Шаблоны длины: short (280–350 зн.), medium (600–900), long (1200–1600).

- Тональности: neutral / supportive / growth-mindset (под ключ США).

- Гардрейлы: без «гарантий», без мед/фин/прав советов; дисклеймер «for entertainment».

- Стабильность: при отсутствии «сильных» транзитов (ниже порога) — выдаём общий «сигнальный» абзац (фаза Луны + правдоподобные сферы из натала).

Персонализация и ранжирование:

- Считаем «вес» события и выбираем топ-2–3 на день:
 score = f(точность аспекта, скорость транзитной планеты, вовлечённый дом/тема, новизна, пользовательские интересы)
 Добавляем персональные настройки: «больше про работу / про отношения / про self-care», «с утра/вечером», «1×/день дайджест или тихие алерты».

- Дополнительные модули:
    - Таро/рунные карты: механика вытягивания карты + собственные трактовки; можно опереться на общедоступные описания как справку, но тексты сделать свои, чтобы не тащить CC BY-SA.
    - Нумерология: быстрые расчёты (дата рождения/имя) → фиксированные «атомы».
    - Wellness-советы: мягкие, немедицинские (сон/рутина/рефлексия), без обещаний.

Техстек и лицензии (коротко):

- Astronomy/astrocalc: Skyfield + JPL DE440 (.bsp) — MIT-friendly, простая установка.

- Гео/время: self-hosted Nominatim + timezonefinder (офлайн), без внешних ограничений.

- Хранилище: PostgreSQL (таблицы: users, birth_data, natal_cache, transit_events, content_atoms, deliveries, payments).

- Кэш: дневные транзиты на 7–14 дней вперёд; регенерация 1×/сутки.

TG-слой: инлайн-кнопки, реактивация «Snooze/More», deeplink-рефералка.

Поток контента день-за-днём (что произойдёт в боте):

- 00:05 локального времени юзера → крон рассчитывает топ-события.
- RAG достаёт 2–4 «атома» + добавляет слой фазы Луны/ингрессий.
- LLM генерит 1–2 абзаца + 1 заголовок + опционально «ритуал/аффирмацию».
- TG-бот отправляет дайджест; при клике «Подробнее» — длинная версия и апсейл PDF.
- Сигналы от пользователя (лайк/дислайк/скрыть темы) летят в фичестор → корректируют веса.

Пример структуры «атома»:

id: T-Mercury_trine_Moon_work

trigger: Mercury △ Moon

house_tags: [III, VI]     # коммуникации, рутина

persona_tags: [work, focus, relationships-soft]

strength_hint: light_to_medium

copy_short: "...короткий абзац на 2–3 предложения..."

copy_long:  "...расширенный абзац 80–120 слов..."

cta: "Назначь 30 минут на deep work"  # нейтральные, немедицинские

## 2) Архитектура контента
Ключевая идея: atoms + orchestrator

- Content atoms (EN/ES/RU) хранятся в БД и подбираются/ранжируются под пользователя.
- Оркестратор: compute → rank → render
- Модульность: `module / kind / payload` (payload в jsonb)

## 5) Telegram bot (MVP поведение, конец Sprint-3)
Команды:
- /start — онбординг:
  - age-gate 18+
  - дисклеймер
  - сбор birth_date / birth_time / birth_place
  - запись в users и birth_data (+ geo/tz)
- /today — ежедневный дайджест:
  - считает транзиты
  - подбирает транзитные атомы
  - даёт day-текст (с учётом интересов и желаемой длинны текста, если заданы)
  - quiet-day fallback
- /snooze — пауза/возобновление доставки (quiet mode / delivery time)
- /plan — показывает фактический план пользователя (по entitlements)
- /upgrade — маркетинговый текст апгрейда (пока без Stripe checkout)
- /settings - позволяет изменить настройки профиля: Язык сообщений, Часовой пояс, Время дайджеста

## 6) Plans & hard gating
PlanCode (common/plans.py):
- demo
- daily (default)
- full
- internal

PlanFeature:
- DIGEST — /today
- STRONG_ALERTS — strong alerts module
- CALENDAR — .ics

Feature matrix:
- demo: DIGEST ✅ (cap/урезанный), STRONG_ALERTS ❌, CALENDAR ❌
- daily: DIGEST ✅ (полный), STRONG_ALERTS ❌, CALENDAR ❌
- full: DIGEST ✅, STRONG_ALERTS ✅, CALENDAR ✅
- internal: DIGEST ✅, STRONG_ALERTS ✅, CALENDAR ✅

Где проверяется:
- strong alerts → `is_feature_allowed_for_user(user_id, STRONG_ALERTS)`
- calendar → `is_feature_allowed_for_user(user_id, CALENDAR)`
- /plan и /upgrade читают активный план через `get_active_plan_code(user_id)` из common.entitlements/common.plans
- названия планов/фич приходят из locales/* (tg.plan.*, tg.upgrade.*)
