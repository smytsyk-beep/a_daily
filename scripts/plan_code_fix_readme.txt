ИСПРАВЛЕНИЕ: plan_code не читался при вызове с length_override
==========================================================================

ПРОБЛЕМА
--------
Пользователи с разными планами (Daily vs Full) получали ОДИНАКОВЫЙ дайджест
при выборе длины "Подробный" (long):

  • План Daily + long -> 6 абзацев (6 атомов)
  • План Full + long  -> 6 абзацев (6 атомов)

Ожидалось:
  • План Daily + long -> cap до medium -> 3 атома
  • План Full + long  -> 6 атомов (без ограничений)

Пользователь платит за Full, но получает то же самое, что и на Daily!

ПРИЧИНА
-------
В файле daily_digest_service.py функция build_daily_digest_for_user:

СТАРЫЙ КОД (БАГОВЫЙ):
```python
plan_code: Optional[str] = None
length_override = length
if length_override is None:  # ❌ Условие FALSE, когда length передан!
    try:
        plan_code = get_user_plan(db, user.id)
    except Exception:
        plan_code = None
    
    if plan_code == "demo":
        length_override = "short"
```

Проблема: когда /today передаёт length (финальная длина после cap),
условие `if length_override is None` равно FALSE, и plan_code НЕ ЧИТАЕТСЯ!

Результат:
  • plan_code = None
  • _compute_max_atoms(length, plan_code=None)
  • План НЕ учитывается при выборе атомов!

НОВЫЙ КОД (ИСПРАВЛЕННЫЙ):
```python
# 1. План пользователя (читаем всегда!)
plan_code: Optional[str] = None
try:
    plan_code = get_user_plan(db, user.id)
except Exception:

# Для плана demo принудительно ставим short, если length не задан явно

if length_override is None and plan_code == "demo":
    length_override = "short"
```

Изменения:
  1. plan_code читается ВСЕГДА (вне зависимости от length)
  2. Логика demo переписана: применяется ТОЛЬКО если length=None
  3. _compute_max_atoms теперь ВСЕГДА получает правильный plan_code

ПРО КЕШИРОВАНИЕ СОБЫТИЙ
==========================================================================

ВАЖНО: События (транзиты) НЕ пересчитываются при смене плана!

События сохраняются в таблице events:
  • kind = "transit_aspect"
  • details["bucket"] = "digest"
  • details["local_date"] = day.isoformat()

Они привязаны к (user_id, day) и НЕ зависят от плана/настроек.

Это ПРАВИЛЬНОЕ поведение:
  1. События (транзиты) одинаковы для пользователя в конкретный день
  2. План влияет на КОЛИЧЕСТВО атомов, выбранных из событий
  3. План НЕ влияет на сами события (астрология не меняется)

Пример:
  • У пользователя 9 событий (транзитов) на день
  • План Daily: выбирается 3 атома из 9 событий
  • План Full: выбирается 6 атомов из 9 событий
  • События НЕ пересчитываются - они уже в БД

Когда пересчитывать события:
  ✅ Новый день (другая дата)
  ✅ Изменение birth_data (дата/время/место рождения)
  ✅ Инвалидация natal_cache
  ❌ Смена плана (события те же, меняется только выборка)
  ❌ Смена настройки длины (события те же, меняется только рендеринг)
